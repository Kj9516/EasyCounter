# EasyCounter

Локальный универсальный конструктор счетчиков для iOS и Android. Пользователь должен создавать собственные проекты, экраны, параметры, правила и виджеты. В приложении не должно быть встроенной предметной логики вроде очков, денег, игроков или здоровья.

Это **нативное мобильное приложение на React Native + Expo + TypeScript**, а не веб-сайт. Репозиторий содержит мобильный исходный код, конфигурацию Expo и вспомогательные Replit-файлы для запуска артефакта.

## Текущий статус

### Реализовано

- Рабочий экран показывает панель текущих параметров (первые два или весь список); в режиме использования скрыты заголовок и панель настройки.
- Таймеры настраиваются в секундах и могут получать длительность из сохраненного числового параметра, в том числе заполняемого действием ввода. В редакторах правил длинные наборы вариантов свернуты до основных значений.
- Тип `duration` не предлагается при создании параметра или временной переменной; он сохранен в движке ради старых проектов и календарных вычислений.

- Expo Router и базовый маршрут: список проектов → экраны проекта → рабочее пространство экрана и настройки проекта.
- Создание, просмотр, дублирование, редактирование и удаление проектов.
- Создание, переименование и удаление экранов.
- Локальная SQLite-схема для проектов и экранов; при создании проекта автоматически создается пустой «Экран 1».
- Автоматические тесты репозитория поверх настоящей временной SQLite-базы Node.js. Запросы и схема общие с приложением; тестовый адаптер только сопоставляет API `expo-sqlite` с Node SQLite.
- Движок этапа B: строгие типы параметров и значений, безопасный парсер выражений, точная десятичная арифметика, списки и календарные значения.
- Статическая проверка условий/формул/действий и блокировка циклов вычисляемых параметров; вычисляемые значения обновляются после каждого изменения.
- FIFO очередь событий, порядок правил, события присваивания и изменения, снимки old/new, триггер «ложь → истина» и сброс значений.
- Изолированное исполнение делится на продолжимые порции и допускает отмену без частичной фиксации.
- Миграции SQLite до версии 11; раздельное хранение конфигурации и runtime, атомарное сохранение завершенной операции и журнала с проверкой версии. Настройка проекта для полей VoiceOver по умолчанию выключена.
- Автотесты движка и SQLite для сценариев этапа B, включая миграцию, формулы, откат и конфликт параллельных операций.

### Статус этапа C

Реализованы редакторы параметров и правил, изменение типа параметра с атомарной переинициализацией runtime, safe-expression редактор с текстовым вводом и построением блоками-кнопками, цепочки действий и временные переменные ввода с ожиданием ответа и атомарной отменой. Экран поддерживает режим редактирования/использования, все базовые типы виджетов из ТЗ, сетку на одну/две колонки, группировку контейнерами, порядок, привязки, варианты выбора, динамические текст/цвет/видимость и доступные подписи. Реализованы сообщения, полная история завершенных операций, очистка истории и сброс. Функциональный объем этапа C и проверки сборки завершены. Ручная приемка native SQLite, специальных возможностей и сохранения после перезапуска на физических iOS/Android устройствах остается открытой; используйте журнал приемки устройств.

### Следующие этапы

- Этап D: реализованы таймеры, периодические и календарные события, восстановление пропущенных интервалов, JSON-архивы шаблона/полной копии и независимый импорт с переназначением ссылок. Экспорт/импорт `.json` использует системные диалоги iOS/Android; перенос через файловые диалоги и проверки движка, SQLite, TypeScript и JS-сборок проходят. Ручная приемка на физических iOS/Android устройствах остается открытой.
- Деление и округление используют десятичную модель с ограничениями из `DECISIONS.md`; дата сдвигается только на полные дни, `time` работает по кругу 24 часов.
- Защита от бесконечного исполнения основана на порционной обработке и API `cancel`/`continue`; обнаружение подозрительных циклов и диалог управления ими относятся к интеграции следующих этапов.

Физический запуск на iPhone или Android, native bridge `expo-sqlite`, экранная доступность и перезапуск приложения на реальном устройстве остаются непроверенными. Node SQLite-тесты проверяют SQL-операции на файловой SQLite, а Expo exports — JavaScript-бандлы; обе проверки не заменяют ручную проверку устройства.

### Последняя проверка

Последний полный прогон выполнен 11 октября 2026 года после реализации этапа D:

- `tsc -p tsconfig.test.json` и `node --test tests/*.test.cjs` — тесты движка, миграций, связей виджетов и SQLite;
- `tsc -p tsconfig.json --noEmit`;
- `expo export --platform ios` в `/tmp/easycounter-stage-d-ios-final`;
- `expo export --platform android` в `/tmp/easycounter-stage-d-android-final`.

Expo export проверяет сборку JS-бандлов, а не запуск или подписание нативного приложения. Тест SQLite создает реальную временную БД Node.js, закрывает ее и повторно открывает файл. На настоящих iPhone и Android-устройствах эти проверки не проводились. Проверялся TypeScript именно EasyCounter, а не всего монорепозитория.

Тесты движка и расписаний — 25/25; SQLite и архивы — 15/15; TypeScript test compilation и app typecheck — успешно; lockfile соответствует package.json; iOS и Android Expo exports — успешно. Expo Go/dev-client и ручная приемка на физических устройствах остаются в отдельной ветке и отмечаются в журнале приемки устройств.

## Технологии и требования

- React Native, Expo SDK 57, Expo Router, TypeScript.
- `expo-sqlite` для локальных данных.
- Node.js 22.13+ и pnpm 10+.
- Лицензия не назначена; `LICENSE` намеренно отсутствует.

## Установка и проверки

Из корня этого репозитория:

```bash
pnpm install
pnpm run test
pnpm run typecheck
pnpm exec expo export --platform ios
pnpm exec expo export --platform android
```

Expo Go/проверка на iPhone настроена в отдельной ветке `iphone-ux-review`; на `main` остаются только продуктовые изменения. Переключитесь на эту ветку, затем для запуска:

```bash
pnpm run start:device
```

Телефон и компьютер должны быть в одной сети. Если LAN-соединение недоступно, настройте Expo tunnel и затем сканируйте QR-код в Expo Go.

## Ручная приемка на телефоне

В Replit запустите workflow **EasyCounter / expo** и откройте QR из его консоли/предпросмотра. На iPhone установите Expo Go и отсканируйте QR штатной камерой; на Android откройте сканер QR в Expo Go. Не используйте web-превью как подтверждение нативного запуска.

Проверьте и зафиксируйте результат каждого шага для этапа A, а затем сценарии этапа C в [`docs/device-acceptance.md`](docs/device-acceptance.md):

1. Открывается список проектов; создание проекта возвращает в список и показывает его.
2. Откройте проект, добавьте экран, переименуйте его и удалите; откройте рабочее пространство экрана и настройки проекта.
3. Переименуйте проект, закройте приложение полностью через переключатель приложений, снова запустите из Expo Go или повторно откройте тот же QR.
4. Убедитесь, что проект, настройки и оставшиеся экраны сохранились после перезапуска.
5. Удалите проект и проверьте, что он исчезает из списка.

Нативный запуск и ручная проверка данных на устройствах должны быть отмечены отдельно для iOS и Android.

## Синхронизация из Replit

В корневом Replit-монорепозитории GitHub настроен отдельным remote `easycounter-public`; внутренний `gitsafe-backup` сохранен. После фиксации изменений публикуйте только подкаталог приложения:

```bash
git subtree push --prefix=artifacts/easycounter easycounter-public main
```

Не выполняйте `git push main` в remote `easycounter-public`: он должен получать только отфильтрованное содержимое EasyCounter, а не соседние артефакты.

## Дорожная карта

- **A — основа:** Expo-приложение, навигация, локальное хранение и проверка на iOS/Android.
- **B — универсальный движок: реализован.** Типы, безопасный парсер, статическая проверка, десятичная арифметика, формулы, FIFO правила/события, изолированное исполнение, атомарный SQLite commit и история.
- **C — редактор: функциональная реализация и JS-сборки завершены.** Ручная приемка native приложения отдельно ожидает запуск на iOS и Android.
- **D — автоматизация и перенос: реализация и JS-проверки завершены.** Подтвердите системные файловые диалоги и end-to-end сценарии отдельно на физических iOS и Android устройствах.

Каждый этап требует отдельной приемки. Следующий этап не считается начатым автоматически.

## Вклад разработчиков

Перед изменениями прочитайте техническое задание и журнал решений. Сохраняйте универсальную предметную модель, не добавляйте встроенные игровые или финансовые сущности и не включайте секреты, `.env`, ключи подписи, `node_modules` или собранные приложения. Перед pull request запускайте команды проверок выше и указывайте отдельно, какие проверки проводились на настоящих телефонах.
