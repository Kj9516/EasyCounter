# Проверка EasyCounter на iPhone и Android

## Что именно проверяется

Сейчас интерфейс содержит этап A: проекты, экраны и настройки проекта. Проверка на телефоне подтверждает запуск настоящего React Native приложения и работу `expo-sqlite` на устройстве. Движок этапа B имеет автоматические проверки и API хранения, но редактор параметров/правил ещё не подключён к экрану, поэтому его сценарии с телефона пока недоступны.

Для проекта используется Expo SDK 57. [Expo Go из App Store на iPhone поддерживает только SDK 54](https://docs.expo.dev/troubleshooting/expo-go-version-mismatch/); для SDK 57 используйте development build этого проекта. Ветка уже настроена под него. Expo Go для Android можно установить под SDK проекта, но для общей проверки обеих платформ используйте указанный ниже development build.

## Что понадобится

- Компьютер с Node.js 22.13+ и pnpm 10+.
- Expo аккаунт; на iPhone Expo Go требует одинаковый Expo аккаунт в CLI и приложении, development build также публикуется из этого аккаунта.
- Для установки iOS development build на физический iPhone — Apple Developer Program аккаунт и регистрация тестового устройства через EAS.
- Телефон и доступ к интернету. Для загрузки проекта используется Expo tunnel; соединение нужно оставить доступным на время теста.

Expo описывает development build как собственную версию клиента с нужными нативными модулями; [инструкция Expo по сборке на устройства](https://docs.expo.dev/develop/development-builds/introduction/) объясняет установку Android APK и iOS internal build.

## Сборка и запуск

Из клона репозитория:

```bash
git switch device-acceptance
pnpm install --frozen-lockfile
pnpm dlx eas-cli login
pnpm dlx eas-cli whoami
pnpm dlx eas-cli init
```

`eas init` свяжет приложение с вашим Expo проектом и добавит его project ID в `app.json`. Убедитесь, что команда выполнилась в каталоге приложения, где лежат `package.json` и `app.json`.

Соберите обе платформы:

```bash
pnpm dlx eas-cli build --profile development --platform android
pnpm dlx eas-cli build --profile development --platform ios
```

EAS покажет ссылки на сборки и инструкции установки. Установите Android APK на телефон по ссылке. Для iOS следуйте шагам регистрации UDID и установки, которые покажет EAS; устройство должно быть включено в provisioning profile. Сборка iOS на физическое устройство требует Apple Developer Program. После установки откройте development build на телефоне.

Запустите Metro из того же клона:

```bash
pnpm run start:device
```

Отсканируйте QR-код системной камерой iPhone или камерой Android, затем откройте ссылку в установленном EasyCounter development build. Если сеть блокирует tunnel, подключите телефон и компьютер к одной Wi-Fi сети и запустите `pnpm exec expo start --dev-client --lan`.

## Сценарии ручной проверки

Сделайте эти шаги отдельно на iPhone и Android. Перед началом удалите только тестовые проекты, оставив на устройстве важные данные нетронутыми.

1. Приложение запускается и показывает список проектов без красного экрана/ошибки в Metro.
2. Создайте проект с русским названием и описанием. Он появляется в списке и открывается.
3. В проекте добавьте два экрана. Переименуйте один, удалите другой и проверьте обновление списка.
4. Откройте настройки проекта, измените название и описание, сохраните изменения.
5. Закройте приложение через переключатель приложений, завершив процесс, затем снова откройте development build и тот же проект. Изменённые сведения и экраны должны сохраниться.
6. Повторите шаги 2–5 в авиарежиме после первой загрузки JS-бандла: записи хранятся локально, сервер для CRUD не используется.
7. Создайте копию проекта. Проверьте, что копия независима: добавьте/удалите экран в копии и убедитесь, что исходный проект не изменился.
8. Удалите копию, затем исходный тестовый проект. Оба должны исчезнуть из списка.
9. Проверьте системную кнопку «Назад» Android и жест/кнопку возврата iOS во время навигации и редактирования.
10. Проверьте клавиатуру и прокрутку: поля названия/описания доступны, кнопка сохранения не закрыта клавиатурой, длинный текст не ломает экран.
